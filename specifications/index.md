This document provides the technical specification for the Multi-Media Interchange Format (MMIF), a JSON-LD format for representing annotations of audiovisual media.

## 1. Top-Level Structure

A MMIF file is a JSON object with three top-level properties: `metadata`, `documents`, and `views`.

```json
{
  "metadata": { ... },
  "documents": [ ... ],
  "views": [ ... ]
}
```

| Property    | Type   | Description                               | Required |
|-------------|--------|-------------------------------------------|----------|
| `metadata`  | Object | Contains metadata about the MMIF file, as defined by the `mmifMetadata` schema object. | Yes      |
| `documents` | Array  | An array of `Document` objects, each representing a source media file. The base structure is defined by the `annotation` schema object. | Yes      |
| `views`     | Array  | An array of `View` objects, each containing annotations from a single CLAMS app. Defined by the `view` schema object. | Yes      |

---

## 2. The `metadata` Property

The `metadata` object contains information about the MMIF file itself, as defined by the `mmifMetadata` object in the JSON schema.

| Property | Type   | Description                            | Required |
|----------|--------|----------------------------------------|----------|
| `mmif`   | String | A URI specifying the version of the MMIF schema that this document conforms to.     | Yes      |

**Example:**

```json
"metadata": {
  "mmif": "http://mmif.clams.ai/$VERSION/schema/mmif.json"
}
```

---

## 3. The `documents` Property

The `documents` property is an array of `Document` objects, where each object represents a source media file (e.g., video, audio, image, text). The base structure for a `Document` object is defined by the `annotation` object in the JSON schema, but all documents in the `documents` array must have a `@type` that is a subtype of `Document` in the [CLAMS Vocabulary](vocabulary).

A `Document` object has two main properties:

| Property     | Type   | Description                                       | Required |
|--------------|--------|---------------------------------------------------|----------|
| `@type`      | String | A URI that identifies the document's type from the [CLAMS Vocabulary](vocabulary) (e.g., `http://mmif.clams.ai/vocabulary/TextDocument/$TextDocument_VER`). | Yes      |
| `properties` | Object | An object containing the properties of the document, as defined by the `annotationProperties` object in the JSON schema. | Yes      |

### 3.1. Document Properties

| Property   | Type   | Description                                       | Required |
|------------|--------|---------------------------------------------------|----------|
| `id`       | String | A unique identifier for the document.             | Yes      |
| `location` | String | The URI of the media file.                        | No       |
| `mime`     | String | The MIME type of the media file.                  | No       |
| `text`     | Object | For `TextDocument`, the inline text content.      | No       |

**Example:**

```json
"documents": [
  {
    "@type": "http://mmif.clams.ai/vocabulary/VideoDocument/$VideoDocument_VER",
    "properties": {
      "id": "m1",
      "mime": "video/mpeg",
      "location": "file:///var/archive/video-0012.mp4"
    }
  },
  {
    "@type": "http://mmif.clams.ai/vocabulary/TextDocument/$TextDocument_VER",
    "properties": {
      "id": "m2",
      "text": {
        "@value": "Sue flew to Bloomington.",
        "@language": "en"
      }
    }
  }
]
```

## 4. The `views` Property

The `views` property is an array of `View` objects, as defined by the `view` object in the JSON schema. Each `View` contains annotations generated by a single processing step (i.e., a CLAMS app).

A `View` object has the following properties:

| Property      | Type   | Description                                       | Required |
|---------------|--------|---------------------------------------------------|----------|
| `id`          | String | A unique identifier for the view.                 | Yes      |
| `metadata`    | Object | An object containing metadata about the view and its annotations, as defined by the `viewMetadata` schema object. | Yes      |
| `annotations` | Array  | An array of `Annotation` objects.                 | Yes      |

### 4.1. View Metadata

The `metadata` object within a view contains information about the app that generated the annotations, as well as metadata about the annotation types themselves.

| Property   | Type   | Description                                                               | Required |
|------------|--------|---------------------------------------------------------------------------|----------|
| `app`      | String | A URI identifying the CLAMS app that produced the view.                  | Yes      |
| `contains` | Object | A dictionary of annotation types present in the view, along with their metadata. | Yes      |
| `timestamp`| String | The ISO 8601 timestamp of when the view was created.                       | No       |
| `error`    | Object | An object describing an error that occurred during processing.           | No       |
| `warnings` | Array  | A list of warning messages.                                               | No       |
|`parameters`| Object | A dictionary of runtime parameters and their string values.               | No       |

**Example:**

```json
"metadata": {
  "app": "http://apps.clams.ai/bars-and-tones/1.0.5",
  "timestamp": "2020-05-27T12:23:45",
  "contains": {
    "http://mmif.clams.ai/vocabulary/TimeFrame/$TimeFrame_VER": {
      "timeUnit": "seconds",
      "document": "m1"
    }
  }
}
```

### 4.2. Annotations

The `annotations` property is a list of `Annotation` objects. Each `Annotation` object represents a single piece of information added to a document.

An `Annotation` object has the following structure:

| Property     | Type   | Description                                       | Required |
|--------------|--------|---------------------------------------------------|----------|
| `@type`      | String | The type of the annotation (e.g., `TimeFrame`).     | Yes      |
| `properties` | Object | A dictionary of properties for the annotation.    | Yes      |

#### 4.2.1. Annotation Properties

All annotations must have an `id` property. Other properties are defined by the annotation's `@type` in the [CLAMS Vocabulary](vocabulary).

| Property | Type   | Description                                       | Required |
|----------|--------|---------------------------------------------------|----------|
| `id`     | String | A unique identifier for the annotation within the view. | Yes      |

**Example:**

```json
"annotations": [
  {
    "@type": "http://mmif.clams.ai/vocabulary/TimeFrame/$TimeFrame_VER",
    "properties": {
      "id": "v1:tf1",
      "start": 0,
      "end": 5,
      "label": "bars-and-tones"
    }
  }
]
```

## 5. Views with Documents

While the top-level `documents` array is static, some applications, like OCR or ASR, generate new documents from existing annotations. These new documents are themselves represented as annotations within a `View`.

For example, an OCR app might process a `BoundingBox` annotation from a previous view and produce a `TextDocument` annotation. This new `TextDocument` can then be consumed by downstream NLP apps.

To link the new document to its source annotation, an `Alignment` annotation is used.

### 5.1. The `Alignment` Type

The `Alignment` type from the [CLAMS Vocabulary](vocabulary) is used to create a relationship between two annotations.

| Property | Type   | Description                                       | Required |
|----------|--------|---------------------------------------------------|----------|
| `source` | String | The `id` of the source annotation (e.g., a `BoundingBox`). | Yes      |
| `target` | String | The `id` of the target annotation (e.g., a `TextDocument`). | Yes      |

### 5.2. Example: OCR

Consider a MMIF file that initially contains an `ImageDocument` and a `View` from an text detection app with a `BoundingBox` annotation.

An OCR app would then add a new `View` containing two key annotations:

1.  A `TextDocument` annotation representing the recognized text.
2.  An `Alignment` annotation linking the source `BoundingBox` to the new `TextDocument`.

```json
{
  "id": "v2",
  "metadata": {
    "app": "http://mmif.clams.ai/apps/tesseract/0.2.2",
    "contains": {
      "http://mmif.clams.ai/vocabulary/TextDocument/$TextDocument_VER" : {},
      "http://mmif.clams.ai/vocabulary/Alignment/$Alignment_VER": {}
    }
  },
  "annotations": [
    {
      "@type": "http://mmif.clams.ai/vocabulary/TextDocument/$TextDocument_VER",
      "properties": {
        "id": "v2:td1",
        "text": { "@value": "yelp" }
      }
    },
    {
      "@type": "http://mmif.clams.ai/vocabulary/Alignment/$Alignment_VER",
      "properties": {
        "source": "v1:bb1",
        "target": "v2:td1"
      }
    }
  ]
}
```

Downstream apps can then process the new `TextDocument` by referencing its ID (`v2:td1`). The `Alignment` annotation preserves the provenance of the text, tracing it back to the specific region of the image it was derived from.

## 6. MMIF and the Vocabularies

The structure of MMIF files is defined in the [schema](schema/mmif.json), but the semantics of what is expressed in the views are determined by the [CLAMS Vocabulary](vocabulary).

Each annotation in a view has two fields: `@type` and `properties`. The value of the first one is typically an annotation type from the vocabulary. The `@type` URL is a page in the published vocabulary that spells out the definition of the type, as well as listing all properties defined for it (whether inherited or not).

The vocabulary also defines `metadata` properties. These are not expressed in the annotation itself, but in the `contains` dictionary of the view's metadata.
